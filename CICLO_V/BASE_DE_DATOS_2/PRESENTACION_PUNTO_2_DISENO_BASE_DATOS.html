El punto 2 organiza productos, ingresos, consumos, proveedores y stock en un modelo relacional.

Productos

Arroz, aceite, verduras, carnes, gas.

Ingresos

Entradas desde proveedores o instituciones.

Consumos

Salidas por preparacion de alimentos.

2.1 Problematica

La informacion esta dispersa

? Que productos hay
? Que ingreso y de quien vino
? Que se consumio y cuanto queda

La solucion no empieza con una aplicacion. Empieza identificando datos y relaciones.

2.4 Atributos

Cada tabla guarda solo lo necesario

Las claves primarias identifican. Las claves foraneas relacionan.

productos id, categoria, nombre, stock, vencimiento
ingreso id, fecha, proveedor
detalle_ingreso id, ingreso, producto, cantidad
consumo id, fecha
detalle_consumo id, consumo, producto, cantidad

2.7 y 2.9 SQL

Tipos corregidos

PK SERIAL
FK INT
FECHA DATE 
CREATE TABLE detalle_ingreso (
  id_detalle_ingreso SERIAL PRIMARY KEY,
  id_ingreso INT NOT NULL,
  id_producto INT NOT NULL,
  cantidad INTEGER NOT NULL CHECK (cantidad > 0),
  FOREIGN KEY (id_ingreso) REFERENCES ingreso(id_ingreso),
  FOREIGN KEY (id_producto) REFERENCES productos(id_producto)
);
